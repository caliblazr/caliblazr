## 2. Roadmap

### v1.1.0 — Stability & Growth (Next Sprint)
**Goal:** Reduce churn, improve activation, harden security

#### P0 — Must Ship
- [ ] **Rate limiting** on `/api/auth/*` — prevent brute force (use `express-rate-limit`)
- [ ] **HttpOnly cookie** for JWT — eliminate XSS token theft risk
- [ ] **Email verification** on register — reduce bot signups
- [ ] **Password reset flow** — users are locked out with no recovery path

#### P1 — Should Ship
- [ ] **Mobile responsive layout** — Sidebar collapses to bottom nav at <768px
- [ ] **Habit completion notes** — users can journal why they succeeded/failed
- [ ] **Weekly summary email** — cron job + nodemailer, recaps habits + streaks
- [ ] **Stripe Checkout integration** — replace upgrade stub with real payment
- [ ] **Google AdSense** — replace mock ad divs with real `<ins>` tags

## 4. Decisions Log

| Date | Decision | Reason | Alternatives Considered |
|------|----------|--------|------------------------|
| Mar 2026 | SQLite over PostgreSQL | Simpler deployment for MVP, WAL mode handles concurrent reads | PostgreSQL (overkill for <1K users), Turso (added complexity) |
| Mar 2026 | Express v5 over v4 | Latest stable, native async error handling | Fastify (less ecosystem familiarity), Hono (too new) |
| Mar 2026 | better-sqlite3 over Drizzle/Prisma | Zero config, synchronous API is simpler for MVP | Drizzle (great for v2), Prisma (too heavy) |
| Mar 2026 | JWT in localStorage over HttpOnly cookie | Faster to ship; migrate to cookie in v1.1 | HttpOnly cookie (v1.1 priority) |
| Mar 2026 | Demo mode for missing API key | Reduces setup friction, app works without Anthropic key | Always require key (too high friction) |
| Mar 2026 | claude-opus-4-6 (not Haiku) | Quality of coaching responses is a core differentiator | Haiku (cheaper but noticeably worse advice quality) |
| Mar 2026 | Tailwind CSS over CSS Modules | Speed of development, consistent utility system | CSS Modules (more isolation), styled-components (runtime cost) |
